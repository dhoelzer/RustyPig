# KNOWN DEVIATIONS

Deliberate, audited departures from the C++ original (snort3 @ fe29cbe7, 2026-11-05).
Each entry cites the original source so parity stays measurable and auditable.

## API shape (mechanical, no behavior change)

- `helpers/bitop.rs` (bitop.h): `set(unsigned int)` takes `usize`; original never
  type-checked larger widths either. Buffer ops identical.
- `helpers/base64_encoder.rs` (base64_encoder.cc): C `encode(data,len,buf)` pointer
  pair becomes `&[u8]` + caller-provided `&mut [u8]`. `nullptr,0` call in the
  original's "null data" SECTION is just `&[]` here. Step machine is line-for-line.
- `helpers/ring.rs` (ring.h/ring_logic.h): the C++ atomics in RingLogic exist only
  because snort used them across threads with relaxed discipline; the port is
  single-threaded `&mut` (Rust enforces it). Index arithmetic (rx=0, wx=1,
  usable=size-2, `full()` never true because it tests count()==sz) preserved
  verbatim including the C++ quirk.
- `helpers/ring.rs::Ring::new` requires `T: Clone + Default` in place of
  C++ `new T[size]` default-construction.
- `helpers/utf.rs` (utf.cc): C `decode_utf(..., int* bytes_copied)` out-param
  becomes `(ok, copied)` tuple return. `convert_character_encoding` (iconv bridge)
  NOT ported yet — depends on libc iconv; returns no equivalent in this layer.
  CharsetCode/CharsetSrc discriminants kept numerically identical (HTTP
  inspectors compare these values).
- `helpers/boyer_moore.rs` (boyer_moore.cc): C `toupper()` (C locale, uint8_t)
  reimplemented as ASCII-only mapping — same as the original's behavior since the
  original relies on locale "C" in unit tests. `search` returns `i64` with -1 for
  miss, mirroring C `int`. Skipping tables index bytes 0-255 exactly.

## Not yet ported (see PORTING_PLAN.md for status)

Everything outside `helpers/` — codecs/, detection/, framework/, main/, etc.
`helpers/{hyper_search, literal_search, json_stream, markup, streambuf, ring2,
lockless_ring, grouped_list, ber, ...}` are next on the queue.

## sfip (sf_ip.rs / sf_cidr.rs / sf_ip_test.rs)

- `inet_pton`/`inet_ntop`(glibc path) reimplemented in pure Rust rather than
  FFI to libc, for hermetic unit tests. Behavior matched to glibc on Linux
  (strict v4 leading-zero rejection is additionally enforced by SfIp::pton,
  exactly like the original). The SfIp::test_features ntop mode is selected
  by an explicit `test_features: bool` arg instead of a static bool.
- `SfIp::set_str()` mirrors `set(src, nullptr)` and therefore FAILS on
  CIDR/masked inputs (C++ returns SFIP_INET_PARSE_ERR when !srcBits and
  bits != 128). Pass-through variant `set_addr_str()` returns (ret, bits)
  mirroring `set(src, &outbits)`.
- `set_check` in tests mirrors `memcmp(&ip1,&ip2,sizeof(struct))` by
  comparing ip8+family (C padded-struct compare includes no other live state).
- ntop returns String; C returned a caller-owned char buffer.
- `SfIpRet` added `LookupUnavailable(17)` (present in current sf_returns.h)
  beyond the C test-harness codes[] array (17 entries) — same numeric layout.

## helpers/grouped_list.rs GroupedList<T>

- C++ raw self-referential linked list ported to an index arena owned by the
  container. Observable semantics (list1 iteration order, group chains with
  push-on-front `group = this`, GrpRef pointer-to-pointer head updates,
  leave_group repeatedly-callable no-op, erase counts) verified against all
  16 Catch sections ported 1:1 to tests/grouped_list_test.rs.
- delete_element() tombstones (value taken via Default) rather than freeing;
  group refs walking a deleted element would be UB in C++ — here they read a
  clean None. No shipped test path hits that case.
- Holder value requires T: Default (C++ default-constructs it).

## ports + parser/parse_ports
- PortObject::group (RuleGroup*) omitted: the detection layer that owns it is
  not ported yet; the field is inert for all ports-layer operations.
- PortVarTable is a HashMap rather than snort GHash (LRU/primetable internals
  are out of scope at this layer). find() returns an owned clone; the only
  C++ caller immediately PortObjectDup's the borrowed pointer, so behavior is
  identical. dump_rule_info add-if-missing gated behind an explicit flag.
- PortObjectParseString returns Result instead of null + errflag in POParser;
  errflag/message readable via POParser::err()/error_string() equivalents.
- POParserGetShort strtoul emulation: 64-bit unsigned long saturation then
  C (int) wrap, matching the observed C++ exactly (100:4294967396 -> 100:100;
  21+ digit runs -> POPERR_BOUNDS). Verified against harness vectors.
- ParseWarning console output (duplicate ports) not surfaced; same 0 return.
- snort3 has NO Catch2 unit suite for ports/parser (unlike sfip/helpers), so
  parity is enforced by replaying ground-truth vectors generated from the
  ORIGINAL C++ sources built out-of-tree (tools/cpp_harness; copy tree is
  gitignored and regenerated by build.sh).

## sfip/sf_ipvar + sf_vartable
- C linked lists (`sfip_node_t*` chains) ported as `Vec<SfIpNode>` with
  cursors; the separate `head_count`/`neg_head_count` counters and their
  C mutation quirks (single-node `list_contains_node` overlap path not
  decrementing count; tail-append loops not decrementing lengths) are
  preserved, so `merge_len` over-counts exactly where the C original does.
- `sfvt_add_str` returns `(SfIpRet, Option<index>)` instead of an out-param
  `sfip_var_t**`; the table owns the vars and `lookup_var` borrows. C++
  callers that mutate the returned pointer in place (and expect the table
  entry to reflect it) map to mutating a clone in tests; observable table
  state after each *add/define* matches C++.
- C stores var `name` as `snort_strdup`'d char* that may be NULL; port uses
  `Option<String>` and treats names as always UTF-8-unsafe-free like C.
- `sfvt_print` (debug dump) and the per-thread `sfip_var_t` arena cleanup of
  `sfvar_alloc`'s `snort_api` pool are omitted; no test consumes them.
- Alias vars (`sfvar_create_alias`) deep-copy lists but share `id` and
  `value`, mirroring C's shallow alias fields.

## helpers/literal_search + boyer_moore_search
- HyperSearch backend omitted (hyperscan is a C library dependency); the
  instantiate() path always returns the Boyer-Moore engine, which is what
  C returns when HAVE_HYPERSCAN is off. Matcher behavior is identical for
  the literal use case covered by the tests.
- C BoyerMooreSearch borrows the caller's pattern pointer; the Rust port
  stores a copy (same bytes) so the object cannot outlive borrowed data.
- C search() bumps a raw pointer by skip[]; Rust slices. skip[c] <=
  pattern_len <= buffer_len in every reachable state, so bounds match.

## helpers/lockless_ring
- Direct translation: same free-running u32 head/tail counters, same
  EMPTY/STORING/STORED/LOADING slot protocol, same round_up_to_power_of_2.
- T: Default replaces C value-initialization of slot payloads.
- USE_MOVE_TO_DEQUEUE template flag kept but inert: Rust reads the payload
  by pointer-move in both branches (C's copy branch needs T copy-ctor).
- C size() else-branch quirk preserved verbatim (head + (UINT32_MAX -
  tail) is 1 below the true wrapping difference past 32-bit rollover).

## helpers/ring2
- Direct translation of the cursor/guard/turn protocol; store is a fixed
  Vec<u8> in UnsafeCell with raw-pointer access (no &/&mut ever alias the
  shared store between the SPSC threads). Validated under Miri with
  -Zmiri-strict-provenance: no UB, no data races.
- Reader::read returns an owned Vec<u8> instead of C's borrowed pointer
  into the store; byte-for-byte the same record, observable difference
  only if a caller dereferenced the record after pop() (no test does).
- Writer::write_len_check(len) exposes C's early length validation
  (data_len == 0 / > UINT32_MAX checked before touching data) so the
  "Oversized record" Catch section is testable without a 4 GB slice.
- C test's per-test-case Ring2 objects are independent test fixtures here;
  Rust re-creates the buffer per #[test] (Catch SECTIONs shared one
  TEST_CASE object; each SECTION started from a fresh REQUIRE empty state,
  so this is equivalent).

## helpers/json_stream
- Sink is dyn std::io::Write instead of std::ostream&; byte output identical
  for all test content.
- C std::quoted(key) emulated: '"' and '\\' backslash-escaped, everything
  else verbatim (glibc default quote/escape chars).
- isprint uses the C "C" locale set (0x20..0x7E) explicitly.
- put() overload set split by name (put_null / put_i64 / uput_u64 /
  put_cstr / put_string_q / put_string / put_f64 / put_true / put_false)
  because Rust has no overload resolution; put_cstr(None) models C's
  put(key, nullptr) -> "null", empty c-string/empty std::string short
  circuits preserved.
- C++ iostream fixed+precision is sticky stream state; here each
  put_f64 formats the value with its own precision ({:.*} == printf %.*f,
  same rounding), so no stream-state leakage either way.

## helpers/ber + framework/cursor core
- Cursor ported with only the fields ber uses (name/buf/size/pos/delta/
  extensible/buf_id/file_pos). Packet* wiring, the CursorData side-table,
  extensible-buffer growth APIs, and the copy-ctor semantics remain TODO
  with the detection layer.
- C Cursor borrows an external buffer pointer (tests point it at
  sub-array views, e.g. buf+4); the Rust Cursor owns a Vec and sub-array
  views are materialized (set("test", &buf[4..])) so ber's cap check
  `total > UINT32_MAX - (c - beg)` computes identically: beg is the view's
  offset-0 base, exactly like C's beg = buf + 4.
- BerReader holds beg/cursor/end as offsets (usize) instead of raw
  pointers; deref guards (cursor+1 > end etc.) kept verbatim.
- C BerElement::data is const uint8_t*; here the offset into the Cursor
  buffer. Both tests comparing data == buf + N check the same number.

## log/obfuscator
- C std::set<Block, by-offset> -> BTreeMap<u32 offset, usize length>:
  identical offset-ordered iteration and identical offset-only element
  identity (the C comparator treats blocks with equal offsets as equal,
  which std::set emplace dedupes on); push()'s replace-if-longer kept.
- C's two-iterator cursor (cur_buf map iterator + it set iterator)
  becomes cur_buf: Option<String> + it: position index; first()/next()
  re-walk the sorted vec. C's UB-ish paths (deref cur_buf when the map
  is empty, next() before first()) return false here instead; no test
  depends on C's behavior there (EmptyList2Test requires next()==false).
- mask_char exposed as const; C header's per-instance getter is static
  in practice (constexpr member).

## utils/util_unfold
- sf_unfold_header/sf_strip_CRLF/sf_strip_LWS take &[u8]/&mut [u8] +
  Option<&mut i32> out-params; C's NULL-buffer guards become length
  checks and are unreachable (callers can't pass null slices).
- sf_unfold_header NUL-termination quirk preserved verbatim: writes NUL
  at out only when n < outbuf_size, else at outbuf_size-1 (which, given
  the loop bound n < outbuf_size, can leave a non-NUL-terminated buffer
  of exactly outbuf_size bytes plus an overwritten last byte, exactly as
  original).
- output_bytes (C *output_bytes = outbuf_ptr - outbuf) returned as the
  second tuple element; matches upstream CHECK(output_len == input_size)
  and CHECK(output_len == output_size) semantics.

## helpers/streambuf
- streambuf get/put-area pointers (eback/gptr/egptr, pbase/pptr/epptr)
  modeled as i64 offsets into the owned store; C pubsetbuf(char*,n) takes
  &[u8] lifetime for input; for output, the `new char[n]` the tests pass
  is taken as Vec<u8> (Rust cannot express caller-owned new[]; the
  take_data() owner-transfer contract is preserved as Vec handoff).
- libstdc++ public entry points (in_avail/sgetc/sbumpc/snextc/sungetc/
  sputbackc/sgetc-pbackfail/sgetn/sputc/sputn/pub*) replicated from
  /usr/include/c++/14 semantics; tests use an istream/ostream emulation
  with the sentry/gcount/badbit/tellg/tellp mechanics of libstdc++ 14
  (read sets eofbit|failbit on shortfall; write -> badbit on sputn
  shortfall; tellg/tellp return -1 when fail/bad; sentry blocks on bad).
- ostreambuf_infl::xsgetn reads [pptr,epptr) like the original quirk;
  C leaves those bytes uninitialized, Rust guarantees 0 (Vec zeroing).
  No upstream test depends on the garbage values.
- C setbuf(nullptr,n>0) on the output buffer is UB-adjacent (setp to a
  null base); Rust collapses it to an empty buffer. Unexercised upstream.

## utils/util
- check_file_size(const char*) instead of FILE* (fileno indirection);
  rotate_file_for_max_size deferred (pure errno/rename/umask plumbing,
  no upstream tests) pending a filesystem-error strategy shared with
  other file-facing subsystems.
- ts_print takes an explicit TimeCfg {thiszone, output_use_utc,
  output_include_year} instead of reaching SnortConfig::get_conf();
  time formatting uses civil_from_days (Hinnant) standing in for
  gmtime_r; verified against date -u.
- str_to_int_vector: C++ std::stoul throws std::out_of_range/
  invalid_argument on bad items; Rust panics on those inputs (same
  crash-level behavior); stoul's 64-bit ul saturation mapped to u64
  saturating + mod 2^32 (C unsigned long was 64-bit there, stoul
  returns unsigned long; callers store into uint32_t so the C
  narrowing was mod 2^32 — pinned in tests? not yet: noted).
- get_random_seed: reads 4 bytes of /dev/urandom with clock fallback
  (C std::random_device behavior varies by libstdc++ config).

## framework/value (+ parameter subset, utils/bits)
- get_addr over-size case: C std::string::copy past the end reads
  uninitialized bytes; Rust zeroes (tests only pin the all-zero result).
- get_addr_raw exact-size case leaves trailing bytes zero in Rust where
  C left string past-the-end bytes; C callers memset first, tests match.
- Value is Clone (std::string members make C copyable too; C has no
  user-defined copy of stringstream* leak — ss is C-leak-on-copy, Rust
  clones it, stricter and safe).
- strtoul: glibc octal overflow clamps at LONG_MAX while decimal wraps
  at ULONG_MAX (probe-pinned); C strtoul(-x) wraps (probe: -1 ->
  ULONG_MAX). Rust replicates both exactly.
- Value::strtol of magnitude == 2^63: glibc strtol saturates LONG_MAX
  (probe), not wraps — modeled.
- str_to_int_vector in utils/util: C std::stoul throws on out-of-range
  (64-bit ul); Rust returns mod-2^32 like the implicit uint32_t
  narrowing the C callers applied before the exception path mattered
  (deviation noted there; revisit when the option parser pins which
  callers exist).
- Parameter: range union (Parameter*/RangeQuery*/char*) and validate()
  deferred to the option-parsing layer; index/find_ported verbatim.
- FixedBitSet<N> = std::bitset<N> subset for the option bit lists.

## hash (hash_key_operations, ghash, primetable)
- HashKeyOperations: only the static_hash constants (seed 3193/scale 719/
  hardener 133824503) are implemented; the randomized ctor needs a
  bit-exact std::mt19937 + uniform_int_distribution port — deferred until
  the detection layer selects per-thread salting (flagged for revisit).
- GHash: typed payload D + arena index handles instead of void*/GHashNode*;
  userkey/userfree map to Rust ownership/Drop. Keys always stored owned
  (C copied unless userkey), including the string NUL terminator, so
  do_hash sees strlen+1 bytes exactly as C.
- GHash(0,...): C constructs then SIGFPEs on first % nrows; Rust
  constructs and panics on first use. nrows<0 => -nrows literal (no prime
  lookup): preserved.
- find_first/find_next: C find_first() advances the cursor before
  returning the head (verified from source; mid-port "fix" reverted).
  C find_next() after remove()-of-current returns a dangling pointer
  (the upstream drain loops rely on freed chunk ->next staying readable:
  UB); Rust ends the scan cleanly at the freed slot — upstream drain
  loops terminate in Rust via the same protocol because the cursor was
  already advanced before the removal.
- dup insert leaves the ORIGINAL data untouched (HASH_INTABLE short
  circuit): pinned by GH find-b2 (7, not 8).

## framework/ips_option + pdu_section
- IpsOption is a concrete base struct here (name+type+hash+==); C's
  virtual eval/action/retry/get_pattern live in the detection layer.
  `option_eq` stands in for operator== (Rust has no user ==, and PartialEq
  is reserved for structural equality).
- Instantiator statics (set_priority/classtype/sid/...) deferred: they
  mutate IpsInfo/RuleStateMap which don't exist yet.
- PduSection::PsError value: C enum sequence => 5 (PS_MAX aliases
  PS_TRAILER=4); section_to_str has 5 entries (no ERROR string).

## hash cache layer (memcap_allocator, hash_lru_cache, xhash, zhash)
- HashNode* raw pointers -> arena indices (Option<usize>) into XHash.nodes;
  link/cursor update order kept verbatim (incl. HashLruCache touch/remove
  cursor rewiring to gprev BEFORE unlink).
- C `void* data` -> `usize` payload handle chosen by the caller (test suites
  use indices into their own payload Vec; NULL_PAYLOAD sentinel for
  `insert(key, nullptr)`). With datasize>0 C memcpy's into an inline blob;
  the port never copies payloads, only handles.
- memcap accounting quirk preserved: free_() decrements unconditionally even
  for foreign nodes; Rust saturates mem_allocated at 0 instead of unsigned
  wraparound (C double-free accounting is UB; pinned in memcap tests).
- xhash test free_anr_lru_delete_free_node_test relies on delete_lru_node()
  returning *false* right after release_node (node sits on the free list, not
  in the LRU cache) — C CHECK(ret == HASH_OK) only passes because false==0.
- XHash::full() quirk preserved: true iff the FREE LIST is empty.
- allocate_node order pinned: free list -> memcap alloc (max_nodes gate) ->
  ANR release_lru_node; ANR walk bounded at XHASH_MAX_RECOVERY_WALK=64 in
  current source (2026 commit), pinned by release_lru_node_walk_is_bounded.
- ZHash uses a Box<dyn HashOps> stand-in for the virtual do_hash; zhash_test
  stubs FlowHashKeyOps::do_hash as unfinalized seed*scale+byte accumulation,
  ported verbatim as flow_test_ops (the real flow_key.cc bob-jenkins mix
  variant defers to the flow layer).
- MemCapAllocator::allocate() returns bool (not the calloc'd pointer); the
  arena allocates the node slot only when accounting permits, matching the
  observable allocation-count behavior.

## hash/lru_cache_local
- C++ template <Key,Value,Hash> -> Rust <K,V> (HashMap; C Hash param had no
  observable behavior in the suite). entry_size passed in explicitly instead
  of compile-time sizeof math; tests pin 2*sizeof(Key)+sizeof(Value)+8
  (x86-64 std::list iterator).
- C returns `Value&` from find_else_create; Rust returns a stable arena handle
  (entry()/set_entry). C references stay valid across splice by luck of
  std::list; the handle model has identical observable reads/writes.
- Constructor WarningMessage on clamp is not emitted (log layer not ported).
- External stats struct by reference -> owned stats + get_stats() copy.

## hash/lru_cache_shared + lru_segmented_cache_shared
- Data = std::shared_ptr<Value> -> Rc<RefCell<Value>>: C tests mutate the
  pointee through the shared_ptr; RefCell models that dynamically and the
  single-threaded port needs no mutex (public lock()/unlock() omitted; C
  cross-thread pinning semantics are provided structurally by Rc liveness).
- Purgatory retained as Vec<Data> (pruned payloads outlive the operation,
  same as C++ delaying destructors past the lock).
- C quirk pinned: stats.bytes_in_use/items_in_use are NEVER updated by
  LruCacheShared itself; suite asserts both == 0. stats struct field order
  is load-bearing (C get_counts() reinterprets it as the peg array).
- LruCacheLocal prunes while current>max AND list.size()>1; LruCacheShared
  prunes while current>max AND !list.empty() (can evict every entry) —
  asymmetry between the two classes preserved.
- SegmentedLruCache get_segment_idx XOR-folds raw key bytes (C
  reinterpret_cast<const uint8_t*>(&val)); Rust reads via
  std::slice::from_raw_parts on the aligned Copy key. segment_count must be
  a power of two (asserted as in C).
- SegmentedLruCache::set_max_size uses integer division per segment, e.g.
  C++ with size 17 over 4 segments => 4 each. C get_max_size() sums the
  per-segment caps (may be < requested); preserved.

## framework/range (RangeCheck)
- C `RangeCheck` methods take `const char*`; Rust `parse`/`validate` take
  `&[u8]` (the rule layer feeds ASCII). `validate(s, r)` takes
  `Option<&[u8]>` for the nullable `r` bound string.
- C `get_num` uses `strtoll` + errno; Rust `c_strtoll` models ERANGE by
  saturating at LLONG_MIN/MAX and *failing* the parse on overflow, matching
  errno != 0 -> false probes: "+9223372036854775808" fails,
  "-9223372036854775809" fails, "-9223372036854775808" succeeds at i64::MIN.
- Octal quirk pinned: "08" fails because strtoll stops at '8' and get_num
  requires the whole token consumed; "0123" = 83 octal.
- `hash()` narrows i64 min/max to u32 exactly as C casts int64_t members to
  uint32_t before mixing; op is hashed as its C enum discriminant (0..8).
- The C probe harness (tools/range_harness) exercises private members because
  the class exposes min/max as protected; the Rust port publishes them
  (range.cc's own UNIT_TEST block does the same via friend access).

## utils/sflsq (SF_LIST)
- C `NODE_DATA = void*`; Rust `SfList<T>` requires `T: Copy` (pointer-shaped
  payloads). Arena indices stand in for `SF_LNODE*`; `ListCursor` stands for
  the `SF_LNODE**` out-parameter.
- `sflist_free`/`free_all`/`static_free_all` reduce to ownership drop in
  Rust; `free_all(cb)` keeps the callback-per-node observable behavior.
- Probe replay pins gcc's right-to-left printf argument evaluation: the
  `rmh/rmt ... cnt=N` lines report the count read *before* the removal call.
- C `sflist_first(nullptr)` sets *v = null and returns null (the `if (!s)`
  guard); Rust cannot name a null list so that branch is unreachable.

## parser/parse_utils
- C `ParseError(...)` writes to the message subsystem; Rust returns error
  strings in the result struct so probes/tests can assert position text
  ("invalid byte code at N", format/range messages) verbatim.
- C `errno` is process-global; Rust `parse_int` returns `errno: i32` with
  the Linux ERANGE value (34). The value returned on the invalid-format path
  is the *unclamped* strtol value, as in C (early return before clamping).
- C state-0 char dispatch relies on `isdigit`/`isspace`/`isxdigit` called on
  possibly-negative chars; for >127 bytes glibc returns 0 for all and the
  Rust ASCII predicates agree, so behavior is identical.
- `parse_byte_code` takes `&[u8]` (C `const char*`); the closing-quote check
  `in[len-1] == '"'` with the decrement-then-stop loop is replayed exactly,
  including the interior-quote entry into hex mode.

## parser/arg_list (ArgList)
- C stores `char*` into argv + a `std::string buf` backing single-char keys;
  Rust clones owned `Vec<u8>` tokens. The `buf.assign(s,1)` quirk (short-opt
  key is exactly one char) is preserved on purpose, not cleaned up.
- C's truthiness test on the pending `arg` pointer distinguishes `--`
  (pending = empty string, still non-null -> flushes key="") from no pending
  arg; Rust models this with pending = Some("") which matches, since the C
  pointer for `--` is to the NUL terminator and thus non-null.
- `get_arg` cannot yield the C sentinel "" vs null ambiguity for val; empty
  Vec means C "".

## framework/ips_action + main/policy (IpsPolicy action variables)
- C keeps the action registry in file-statics mutated at plugin load
  (PluginManager -> ActionManager::get_interface); Rust threads an explicit
  &mut ActionRegistry so tests control registration order deterministically.
- IpsAction* payloads: policy.action / configured_action hold Option<()>
  placeholders until the actions/ layer exists; get_action()'s selector-vs-
  type-array indexing split (selector 0 -> action[type], else
  configured_action[selector]) is ported verbatim around the placeholders.
- C policy.cc cannot compile hermetically (DAQ, DataBus, Shell); its 3 Catch
  cases were ported by reading and pinned indirectly via the compiled-
  original ActionManager registry harness (tools/action_harness).
- get_interface duplicate-name quirk pinned: unordered_map::emplace does not
  overwrite, but s_act_index++ fires unconditionally, so a re-registered name
  burns a type index forever (vector MAX2 = 7 with only 6 names).
- get_action_priorities alert_before_pass expansion appends "alert pass "
  with trailing space and skips the normal separator logic (`continue`),
  reproduced exactly including double-space artifacts on adjacent entries.

## parser/vars + parser/var_dependency + parser/parse_conf (ParseIpVar)
- C logs ParseError/ParseWarning/ParseAbort through file-globals with
  printf semantics, and ParseAbort longjmps out of every frame. The port
  pushes ordered ParseMsg values onto VarContext.diag and returns
  ParseAbort as Err (message recorded in diag first). No abort unwinding
  is attempted beyond the Err: C's longjmp targets (recovery points,
  DAQ, Shell) do not exist in the port yet.
- C reaches the three var tables + var_id through get_ips_policy() and
  the two weak lists through var_dependency.cc file-statics. The port
  threads one &mut VarContext; resolve()/set_variable() take a split
  borrow (&mut list + &mut ctx) — the C callback *can* push to the same
  weak list mid-resolve (is_resolving_* guards the push path instead);
  the split borrow makes that structurally impossible, which is exactly
  what C's guard enforces for every reachable path.
- VarEntry: C circular doubly-linked list hung off IpsPolicy; the port
  keeps a Vec with head at index 0 and reproduces insert-after-head
  (t.insert(1)) so walks match the C head->next chain. addrset
  (sfip_var_t*) is not carried at this layer — nothing in vars.cc sets
  it; the config_file layer will attach it with DeleteVars support.

## utils/cfmt (C-printf engine) + log/messages.{h,cc} + log/log_errors.h
- snort3 formats through glibc vsnprintf/printf/syslog. The port has zero
  external crates, so utils/cfmt re-implements the C-printf subset the log
  layer actually uses, pinned byte-for-byte against glibc by the
  tools/log_harness vector battery (P17/P17b: ~30 format strings). Not a
  general printf: no positional args ($n), no %a/%td beyond slots, no
  wchar, nonlocalizable.
- Arg values are passed as a typed slice (I/U/F/S) instead of C varargs;
  the int-slot masking (bare %d keeps low 32 bits sign-extended, %hd
  %16-bit wraps etc.) reproduces the ABI truncation the C call sites get.
- FatalError: C _exit(EXIT_FAILURE)s; the port returns Fatal::Quitting
  and keeps already_fatal on the engine so the reentry guard matches
  (second call prints NOTHING, returns Reentrant = C _exit(1)).
  in_main_thread() worker-abort branch and cleanup_fatal_error() stay with
  the embedding binary.
- log_safec_error: C assert(false) (SIGABRT in release-less builds); the
  port panics after the <1000-gated ErrorMessage. The harness vector for
  P14 includes the glibc assertion note line (prints the harness's own
  path) — stripped from the replay expectation; everything before it is
  compared exactly.
- parse_errors/parse_warnings/reload_errors and the reload description are
  plain u32/String, not std::atomic (snort3's are process-wide atomics;
  the port's engine is single-threaded per-policy). get_parse_errors/
  warnings stay destructive read-and-clear like C; get_reload_errors does
  NOT reset.
- warning_flags / logging_flags / output_flags / log_quiet_bypassed are
  SnortConfig CLASS statics in C: they persist even when get_conf() ==
  nullptr. The port keeps them directly on LogEngine (faithful: no deref
  needed to read a static) plus a conf_present bool standing for
  get_conf() != nullptr, gating exactly the two sites that deref the
  object (ParseWarning's suppression guard, WriteLogMessage's buffered
  check). The get_quiet/syslog/buffered accessors mirror the C inline functions.
- BatchedLogger (use_log_buffered / OUTPUT_FLAG_LOG_BUFFERED) is not
  ported: WriteLogMessage panics if the bit is armed, matching the
  harness abort() that made the path observable.
- ConfigLogger: C's 12 log_limit / 9 log_value integer overloads collapse
  to signed/unsigned pairs (i64/u64); disable-vs-unlim precedence and
  the (long long) casts keep output identical. log_list keeps the C
  quirks: head fmt "%*s%s%.0s%s" swallows the prefix (printed only on
  continuation lines), null caption prints glibc "(null)", the 75-char
  wrap test is res.length()+val.length() BEFORE adding ' '+val, and the
  uncaptioned log_list(list) variant uses its own no-leading-space
  accumulation + tab\t continuation.

## parser/parse_so_rule.rs (so-rule stub FSM)
- C walks const char* as raw chars; the Rust port scans bytes and pushes
  chars from byte values. Rules reaching --dump-dynamic-rules are ASCII
  (the FSM only compares against ASCII punctuation and std::isspace is
  the C-locale set), so byte-scanning is equivalent; a non-ASCII UTF-8
  byte would behave exactly as the char value C's (signed) char would for
  isspace purposes — none of the comparison branches treat it specially.

  operator==), and both operands alias when accum==&stub. The port keeps
  a Target enum (Stub/Opt) and replicates: Stub side always sets prev,
  Opt side only when opt content == stub content (vectors exercise both
  the equal and unequal Opt paths).

## utils/util_jsnorm.{h,cc} (row 17i)

Structural (safety-relevant, behavior preserved):

- C threads ONE shared byte buffer through the nested decodes by
  pointer aliasing (SFCC output buffer = Unescape src = Unescape dst;
  Unescape output = PNorm src = PNorm dst). Rust passes a per-stage
  snapshot read view + the same write buffer. Safe because every scan
  step writes at most one byte where it has already consumed one, so
  the write cursor never overtakes the read cursor of the stage.
- Dbuf `data` pointer + size/len -> `size`/`len` over a caller-owned
  slice. All C pointer arithmetic (`overwrite`, `cur_ptr`,
  outBounds) becomes plain index arithmetic.
- `iis_unicode_map` (raw `uint8_t*`, caller-owned, possibly null) ->
  `Option<&[u8]>` cloned into the decode state. C's `unicode_map[iNorm]`
  with iNorm up to 0xffff would read far past any real table (UB); the
  Rust port substitutes NON_ASCII_CHAR for out-of-table indexes —
  unreachable with the pinned 256-byte map in the transcript.
- `strtoul(buf, &p, radix)` -> hand-rolled same-radix accumulation
  (digits are already class-checked by the FSM; 8 digits max, no
  overflow); the C `int` assignment of the unsigned result is a
  bit-identical u32->i32 wrap.
- `ConvertToChar`'s `buf[buflen] = ANY` can write index 8 of a
  `uint8_t buf[8]` (stack OOB in C, value never read). The Rust
  buffer carries the extra slot so the store is literal, not UB.
- Table event bytes: class-marker rows carry IS_* bit values in an
  `event` u8 exactly as C does; `valid_chars`/`hex_lookup` recomputed
  as provably-equal functions (class masks / digit values) instead of
  copied 256-row literals.

Fidelity quirks kept literal:

- `hex_lookup[c]` returns −1 for non-hex bytes; `iNorm <<= 4;
  iNorm |= −1` poisons every bit. Reachable because class-marker
  rows ALSO match via the raw `m->event == uc` comparison: input
  bytes 0x01/0x02/0x04 are numerically equal to IS_OCT/IS_DEC/IS_HEX
  and therefore match those rows with a garbage byte (CONV-style arms
  then see `hex_lookup[c] = -1`). Kept as C `int` semantics
  (wrapping_shl + sign-extended or); not pinned by the locked
  transcript but transcribed literally.
- The `iNorm == -1` check after a u8 unicode_map read is dead in C
  (cppcheck-suppressed `knownConditionTrueFalse`); kept literally.
- Unescape RET_INV pointer step-back is commented out in C; the
  comment is kept commented. SFCC's step-back (`(*ptr-1) > start`)
  is live and transcribed (usize-guarded, never saturates).
- `PNORM_ACT_WITHIN_QUOTES` SWITCH-falls-through into `default:`
  (no-op) — arm simply ends.
- UNESC_ACT_SPACE returns BEFORE the switch-tail `prev_event = c`
  store when the quote branch fires; the early `return` is literal.
- `multiple_levels` is u8 and `num_spaces` u16 in C; Rust wraps them
  the same way (`wrapping_add`), the alerts compare via `i32::from`.
- C allocates the 65535-byte `decoded_out_vec` on EVERY `JSNorm_exec`
  call whatever the action; Rust allocates the equivalent local Vec
  in the function body (allocation itself is not transcript-visible).
- `js == nullptr` contract: returns RET_QUIT before touching `*ptr`
  or `*bytes_copied` (vector row N12); Rust models it as
  `Option<&mut JsState>` with the same untouched-caller-state shape.
