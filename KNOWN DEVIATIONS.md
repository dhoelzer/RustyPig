# KNOWN DEVIATIONS

Deliberate, audited departures from the C++ original (snort3 @ fe29cbe7, 2026-11-05).
Each entry cites the original source so parity stays measurable and auditable.

## API shape (mechanical, no behavior change)

- `helpers/bitop.rs` (bitop.h): `set(unsigned int)` takes `usize`; original never
  type-checked larger widths either. Buffer ops identical.
- `helpers/base64_encoder.rs` (base64_encoder.cc): C `encode(data,len,buf)` pointer
  pair becomes `&[u8]` + caller-provided `&mut [u8]`. `nullptr,0` call in the
  original's "null data" SECTION is just `&[]` here. Step machine is line-for-line.
- `helpers/ring.rs` (ring.h/ring_logic.h): the C++ atomics in RingLogic exist only
  because snort used them across threads with relaxed discipline; the port is
  single-threaded `&mut` (Rust enforces it). Index arithmetic (rx=0, wx=1,
  usable=size-2, `full()` never true because it tests count()==sz) preserved
  verbatim including the C++ quirk.
- `helpers/ring.rs::Ring::new` requires `T: Clone + Default` in place of
  C++ `new T[size]` default-construction.
- `helpers/utf.rs` (utf.cc): C `decode_utf(..., int* bytes_copied)` out-param
  becomes `(ok, copied)` tuple return. `convert_character_encoding` (iconv bridge)
  NOT ported yet — depends on libc iconv; returns no equivalent in this layer.
  CharsetCode/CharsetSrc discriminants kept numerically identical (HTTP
  inspectors compare these values).
- `helpers/boyer_moore.rs` (boyer_moore.cc): C `toupper()` (C locale, uint8_t)
  reimplemented as ASCII-only mapping — same as the original's behavior since the
  original relies on locale "C" in unit tests. `search` returns `i64` with -1 for
  miss, mirroring C `int`. Skipping tables index bytes 0-255 exactly.

## Not yet ported (see PORTING_PLAN.md for status)

`helpers/{hyper_search, literal_search, json_stream, markup, streambuf, ring2,

## sfip (sf_ip.rs / sf_cidr.rs / sf_ip_test.rs)

- `inet_pton`/`inet_ntop`(glibc path) reimplemented in pure Rust rather than
  FFI to libc, for hermetic unit tests. Behavior matched to glibc on Linux
  (strict v4 leading-zero rejection is additionally enforced by SfIp::pton,
  exactly like the original). The SfIp::test_features ntop mode is selected
  by an explicit `test_features: bool` arg instead of a static bool.
- `SfIp::set_str()` mirrors `set(src, nullptr)` and therefore FAILS on
  CIDR/masked inputs (C++ returns SFIP_INET_PARSE_ERR when !srcBits and
  bits != 128). Pass-through variant `set_addr_str()` returns (ret, bits)
  mirroring `set(src, &outbits)`.
- `set_check` in tests mirrors `memcmp(&ip1,&ip2,sizeof(struct))` by
  comparing ip8+family (C padded-struct compare includes no other live state).
- ntop returns String; C returned a caller-owned char buffer.
- `SfIpRet` added `LookupUnavailable(17)` (present in current sf_returns.h)
  beyond the C test-harness codes[] array (17 entries) — same numeric layout.

## helpers/grouped_list.rs GroupedList<T>

- C++ raw self-referential linked list ported to an index arena owned by the
  container. Observable semantics (list1 iteration order, group chains with
  push-on-front `group = this`, GrpRef pointer-to-pointer head updates,
  leave_group repeatedly-callable no-op, erase counts) verified against all
  16 Catch sections ported 1:1 to tests/grouped_list_test.rs.
- delete_element() tombstones (value taken via Default) rather than freeing;
  group refs walking a deleted element would be UB in C++ — here they read a
  clean None. No shipped test path hits that case.
- Holder value requires T: Default (C++ default-constructs it).

## ports + parser/parse_ports
- PortObject::group (RuleGroup*) omitted: the detection layer that owns it is
  not ported yet; the field is inert for all ports-layer operations.
- PortVarTable is a HashMap rather than snort GHash (LRU/primetable internals
  are out of scope at this layer). find() returns an owned clone; the only
  C++ caller immediately PortObjectDup's the borrowed pointer, so behavior is
  identical. dump_rule_info add-if-missing gated behind an explicit flag.
- PortObjectParseString returns Result instead of null + errflag in POParser;
  errflag/message readable via POParser::err()/error_string() equivalents.
- POParserGetShort strtoul emulation: 64-bit unsigned long saturation then
  C (int) wrap, matching the observed C++ exactly (100:4294967396 -> 100:100;
  21+ digit runs -> POPERR_BOUNDS). Verified against harness vectors.
- ParseWarning console output (duplicate ports) not surfaced; same 0 return.
- snort3 has NO Catch2 unit suite for ports/parser (unlike sfip/helpers), so
  parity is enforced by replaying ground-truth vectors generated from the
  ORIGINAL C++ sources built out-of-tree (tools/cpp_harness; copy tree is
  gitignored and regenerated by build.sh).
